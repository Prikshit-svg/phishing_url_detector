# Phishing URL Detection — Explainable ML

A reproducible machine-learning project that classifies URLs from lexical URL features. The application **does not visit submitted URLs** and does not query DNS, inspect live TLS certificates, or determine a server's physical location.

## Project structure

- `features.py` — shared, deterministic URL feature extraction and clearly labeled heuristic indicators.
- `train.py` — dataset cleaning, domain-grouped holdout, model comparison, evaluation plots, and model artifact generation.
- `phishingdetection.ipynb` — guided notebook for audit, training, metrics, and graph review.
- `app.py` — Streamlit URL analysis and model-evaluation dashboard.
- `dataset.csv` — input dataset. The existing engineered columns are ignored by training and regenerated from `url`.
- `best_model.pkl` — generated by training; intentionally not required to be committed.
- `artifacts/` — generated evaluation metrics, CSV summaries, and plots.

## Setup

Use Python 3.10 or newer in a virtual environment.

```bash
python -m venv .venv
# macOS/Linux
source .venv/bin/activate
# Windows PowerShell: .venv\Scripts\Activate.ps1
python -m pip install --upgrade pip
pip install -r requirements.txt
```

## Train and evaluate

Run from the project directory:

```bash
python train.py
```

To specify a dataset path:

```bash
python train.py --data path/to/dataset.csv
```

The script creates `best_model.pkl` and `artifacts/`, including:

- `metrics.json` — split details, audit summary and held-out metrics.
- `model_comparison.csv` and `model_comparison.png` — validation model selection.
- `roc_curves.png` and `precision_recall_curves.png` — held-out model comparison.
- `confusion_matrix.png`, `calibration_curve.png`, `threshold_analysis.png`.
- `permutation_importance.png` and `permutation_importance.csv`.
- `class_distribution.png`.
- `adaptive_learning_experiment.csv` and `adaptive_learning.png` when the grouped batches support the experiment.
- `cross_validation_folds.csv` and `cross_validation_summary.csv` — five-fold domain-grouped metrics (mean and standard deviation) on a bounded sample from the training partition.
- `robustness_perturbations.csv` — held-out phishing recall and evasion rates after deterministic query, path, and subdomain edits.
- `explanation_benchmark.json` — measured SHAP/LIME latency and five-seed LIME attribution cosine similarity, when the optional explainability packages run successfully.

Model selection uses validation F1. The held-out test partition is used for final reporting and graphs, not model selection. The domain grouping is an approximation and may not correctly identify all registrable domains; a Public Suffix List and an external, timestamped test set are recommended for stronger evaluation.

## Run the application

Train first, then run:

```bash
streamlit run app.py
```

Use the sidebar to switch between **URL analysis** and **Model evaluation**. The application uses the same `features.py` implementation as training. If model artifacts are missing, the evaluation page explains how to create them.

## Label and evaluation cautions

- Expected labels are `0 = legitimate`, `1 = phishing`; verify this convention and the original dataset's label quality before interpreting metrics. The code cannot independently establish ground truth.
- Dataset features are recomputed from URLs to prevent stale feature columns from silently entering training.
- Duplicate URLs are removed. Domain-grouped splitting reduces, but does not eliminate, possible leakage.
- The supplied dataset has no reliable timestamps. The adaptive-learning graph is a deterministic group-batch simulation, **not** evidence of real temporal drift or live adaptation.
- Predicted probability is not guaranteed to be calibrated. The default threshold is 0.5; select a deployment threshold on validation data based on the relative cost of missed phishing and false alarms.
- SSL, DNS and region panels are lexical/TLD heuristics. They are not live checks and must not be represented as verified infrastructure facts.
- Pickle files can execute code when loaded. Only load `best_model.pkl` generated by this project or from a trusted source.

## Reproducibility

The pipeline fixes random seeds, writes the chosen split method and metrics to JSON, and generates graphs from the current run. Record the Python and package versions with any final report. Do not quote earlier notebook outputs as current results; rerun the notebook or `train.py` from a clean environment.

## URL-level research visualizations

The URL Analysis page now includes additional evidence views alongside the probability gauge and SHAP/LIME explanations:

- **SHAP waterfall:** local contributions from the model baseline to its output, with smaller features aggregated.
- **Feature-profile radar:** empirical percentile ranks for selected URL characteristics compared with class reference medians.
- **Reference distribution:** URL-length distributions for both labeled classes with the scanned URL marked.
- **Calibration reference:** held-out calibration bins with a marker for the current URL probability.
- **Threshold trade-off:** validation precision/recall/F1 curves with the deployed threshold highlighted.
- **Heuristic indicator chart:** points from the separate rule-based threat score; these are not model probabilities.
- **Model disagreement:** probabilities from the selected model and lightweight comparison fits. This is qualitative only; comparison fits are not benchmark models and their spread is not a confidence interval.
- **Explanation sensitivity:** cosine similarity of SHAP contribution vectors for the original URL and controlled path/query variants. These are distinct URLs and the chart is not a guarantee of robustness.

The Model Evaluation page also includes performance by overlapping URL categories when the subgroup artifact is available. Category metrics are descriptive and should be interpreted alongside sample counts.

The evaluation dashboard also reports five-fold domain-grouped cross-validation, controlled URL perturbation results, and SHAP/LIME latency with LIME repeatability. Cross-validation is bounded to 25,000 training rows for practical local runs; it is not a substitute for an independent external benchmark. Perturbation results describe only the specified lexical edits. CNN/LSTM and third-party filter comparisons are not reported because this project does not include those implementations or matched published benchmark measurements.

### Research interpretation cautions

All of these visualizations are evidence about the model, its features, or the supplied dataset—not proof that a URL is malicious. Dataset label quality has not been independently verified. The application does not visit URLs, query DNS, validate TLS certificates, or determine server geolocation. The calibration and threshold graphs are population-level evaluation results and are not calculated from a single scanned URL. For publication, validate on an independent, timestamped dataset where possible and document label provenance, domain leakage controls, threshold selection, and subgroup sample sizes.
